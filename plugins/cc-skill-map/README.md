# cc-skill-map

Claude Code を起動したディレクトリで使えるスキル(`/name` で呼べる、手順を書いた指示書)を一覧にし、
選んだスキルの手順の流れをペインに図で出す mod です。
スキルが何をして、どこで人の承認を待ち、どのサブエージェント(Claude が作業を分担させる子のエージェント)に任せ、何を残すのかを、
SKILL.md を読み返さずに把握できるようにします。

## できること

- **`/cc-skill-map`** でペインを開き、セッションで使えるスキルを出どころ(プロジェクト・ユーザー・プラグイン・同期・組み込み)ごとに並べます
  - そのスキルをサブエージェントに持たせていれば(エージェント定義の frontmatter の `skills:`)、`← エージェント名` を添えます
  - SKILL.md の `description` を薄く添えます
- スキル名を押すと、そのスキルの手順の流れを組織図にして、実行される順に再生します。`/cc-skill-map <スキル名>` で直接開くこともできます

```
╭─ メイン ─────────────────────────────╮        ╭─ 人 ─────────────────────────╮
│ ┌───────┐ ⠧ 手順 4/5                 │        │ ┌───────┐ ✓ 2/2 手順         │
│ │ キャラ │ researcher に依頼          │        │ │ キャラ │                    │
│ │       │ 調べる                     ├────────┤ │       │                    │
│ └───────┘ 成果物 1                   │        │ └───────┘                    │
╰───────────────────┬──────────────────╯        ╰──────────────────────────────╯
  ╭───────●─────────┴─────────╮
  │                           │
╭─┴─ researcher ─────────╮  ╭─┴─ スクリプト ─────────╮
│ ⠧ 調べる               │  │ 保存する               │
│ 0/1 手順               │  │ 0/1 手順               │
╰────────────────────────╯  ╰────────────────────────╯

手順
✓ 1 メモを受け取る 人
✓ 2 整える AI
✓ 3 確かめる 人 ⏸ ↩2
⠧ 4 調べる サブエージェント researcher
· 5 保存する スクリプト
成果物 ▸ 下書き
```
(ターミナルでの、再生の途中の見え方。メインがサブエージェント researcher に依頼し、依頼の粒 `●` が線を下りているところ。「キャラ」のところにドット絵を描きます)

### 組織図

スクロールせずに全体が見えるよう、ペインの高さに収めて描きます。

- 上段の左に**メイン**のカード、右に**人**のカードを並べます
  - メインのカードには、メインが今していること(自分で進めている手順、誰に依頼しているか、誰の承認を待っているか)と、次にやることを出します。再生していないときは、自分で進める手順と依頼する手順の数、承認の数を出します
  - 人のカードには、人の手順を並べます(終えたものに `✓`、今のものに回る印)。人がどこで関わるかが一目で分かります
- ターミナルでは、メインと人のカードにドット絵のキャラを描きます(`Raster` 要素。マスに色と文字を置いて描く絵)。メインは cc-work-log と同じ現場監督、人は承認印を持つ人(どちらもこのリポジトリのオリジナル)です。デスクトップ版には `Raster` が無いので、キャラを省いて見出しに `◉` を付けます
- カードと箱の手順名は、切り詰めずに2行まで折り返します。ペインの本体が 30 行以上あれば、カードの中身をキャラの下まで広げて行を増やします
- メインの下に、**スクリプト**(1つの箱)と**サブエージェント**(名前ごとの箱)を組織図のように並べます。箱には今の手順と、終えた手順の数を出します。横に入りきらなければ後ろを省きます(「ほか n 体を省いた」)
- その下に**手順**を1行ずつ並べます。番号・手順名・担い手、承認を待つ所に `⏸`、戻り・飛び先に `↩2` / `↪5` を添えます。今の手順だけを太くし、終えた手順は薄く出します。高さに入りきらなければ、今の手順のまわりだけを出し、前後は「… n 手順」にまとめます
- 最後に**成果物**を1件1行で並べます。入りきらなければ新しいものを残し、古いものは「ほか n 件」にまとめます(行がほとんど無いときは、件数と最新の1件だけを1行で出します)
- ペインの幅が 66 マスより狭いときは、手順の箱を縦に積む見せ方にします(この場合はスクロールが要ることがあります)。サブエージェントの手順は、幅が 42 マス以上あればメインの列から横に出します

### 再生

開くと、手順を実行される順にたどります。cc-work-log のマップと同じく、線の上を粒が流れます。スキルを実際に動かすわけではありません。

- メインが自分で進める手順(AI)では、メインのカードが光り、キャラがツルハシを振ります
- スクリプト・サブエージェント・人の手順では、メインから依頼の粒 `●` が線を渡り、相手の箱やカードが光ります。作業のあと、結果の粒 `◆` がメインへ戻り、メインのキャラが喜びます
- 人の出番のあいだ、人のキャラは承認印を掲げ下ろしします。承認を待つ手順では少し止まり、「⏸ 承認待ち」を点滅させます
- 手順の一覧では、今の手順に回る印、終えた手順に `✓` を付けます。戻りをたどるときは、戻りの印を光らせます(戻りは1回だけたどります。戻り先しか書かれていない手順も、戻ったあと並びの次へ進みます)
- 成果物は手順を終えたときに増え、出たばかりのものは光ります。最後にスキル全体の成果物を足します
- `p` で止める・再生する、最後まで行ったら「もう一度」。描き直すのは再生しているあいだだけです(0.15 秒ごと)

### 操作

- `b` で一覧に戻り、`r` で一覧と流れを読み直します

## 流れの読み取り方

SKILL.md は自由に書かれた文書なので、モデルで読み取って流れにします。

- 読み取るのは、スキルを開いたときだけです。結果は、スキルの本文のハッシュと使ったモデルと一緒に保存し(`$.store`。セッションをまたいで残る mod の保存領域)、本文もモデルも変わらないあいだは使い回します。SKILL.md を書き換えると、次に開いたときに読み取り直します
- 読み取りにはプランの使用量を使います。**SKILL.md の本文が、セッションと同じ経路でモデルの API に送られます**
- `/config` の、この mod の項目で、読み取りに使うモデルを選べます

| 項目 | 値 |
| --- | --- |
| `flowModel` | `off` / `haiku`(初期値) / `sonnet` / `opus` / `custom` |
| `flowModelCustom` | `custom` を選んだときに使うモデル ID や略称 |

- `off` にすると、モデルを使わず、SKILL.md の見出し(`##` / `###`)を並べた簡易な流れを出します。担い手・承認・成果物は出ません
- 読み取りに失敗したとき(応答の形が崩れた・API エラーなど)も、理由を添えて見出しの流れで代えます
  - 一時的な失敗(混雑・5xx・時間切れ・応答の崩れ)なら、次に開いたときにまた試します
  - 直らない失敗(モデルが使えない・権限が無いなどの 4xx)なら、同じモデルのあいだは開いても読み取り直しません。「読み直す」を押すと試します

## SKILL.md の探し方

スキルの一覧は Claude Code のコンテキストの内訳(`/context` と同じもの)から取ります。一覧には SKILL.md の場所が無いので、出どころから探します。

| 出どころ | 探す場所 |
| --- | --- |
| プロジェクト | 起動したディレクトリからホームの手前までの `.claude/skills/<名前>/SKILL.md` |
| ユーザー | 設定フォルダ(`CLAUDE_CONFIG_DIR`、無ければ `~/.claude`)の `skills/<名前>/SKILL.md` |
| プラグイン | インストールしたプラグイン(`plugins/installed_plugins.json`)と、同期されたプラグイン(`plugins/synced/`)の `skills/<名前>/SKILL.md` |
| 同期 | 設定フォルダの `skills/synced/` の下 |
| 組み込み | ファイルが無いので、そのセッションで一度呼ばれたときの本文を使います。呼ばれるまでは理由だけを出します |

サブエージェントとの対応は、設定フォルダとプロジェクトの `agents/*.md` の frontmatter の `skills:` から取ります。

SKILL.md とエージェント定義は読むだけで、書き換えません。

## やらないこと

- 実行中のスキルが今どの手順にいるかは追いません
- MCP など、置き場の分からないスキルは名前だけを出します

## インストール

```
/plugin install cc-skill-map --marketplace lu-llc-jp/lu-claude-mods
```
